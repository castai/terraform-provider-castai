# castai_evictor (Resource)

CAST AI evictor resource to manage evictor configuration

## Example Usage

```terraform
resource "castai_evictor" "evictor" {
  cluster_id = castai_eks_cluster.test.id

  enabled                                = true
  dry_run                                = false
  aggressive_mode                        = false
  scoped_mode                            = false
  cycle_interval                         = "60s"
  node_grace_period_minutes              = 10
  pod_eviction_failure_back_off_interval = "30s"
  ignore_pod_disruption_budgets          = false
  soft_tainting                          = false
  emit_node_related_pod_events           = false

  # The fields below are exposed in the V2 API proto and are settable in
  # Terraform. They may not be active in the backend yet and will become
  # functional as backend support rolls out.
  drain_timeout                = "10m"
  drain_rollback_timeout       = "1m"
  windows                      = false
  force_disable_live_migration = false
  force_disable_woop           = false
  force_disable_pod_mutations  = false
  force_disable_karpenter_mode = false
  max_target_nodes_per_cycle   = 0
  min_target_nodes_per_cycle   = 0
  target_node_percentage       = 0
  pricing_awareness_enabled    = false
  arm64_supported              = false

  pricing_model {
    base_cpu_cost = "0.5"
    base_mem_cost = "0.5"
    spot_discount = "0.5"
  }
}
```

> **Note:** Fields `drain_timeout` through `arm64_supported` (13 fields) exist in the V2 API proto but may not be active in the backend yet. They are included for forward compatibility and will become functional as the backend wires them.

## V1 migration

The V1 `castai_autoscaler` resource had evictor settings nested under `node_downscaler.evictor` with only 3 fields (`enabled`, `dry_run`, `aggressive_mode`). The new `castai_evictor` resource exposes all 24 evictor config fields via the standalone workload-eviction API.

See [`castai_autoscaler_policies`](autoscaler_policies.md) for the full V1→V2 migration guide.

## Schema

### Required

- `cluster_id` (String) CAST AI cluster id.

### Optional

- `aggressive_mode` (Boolean) Enable/disable aggressive mode. By default, Evictor does not target nodes that are running unreplicated pods. This mode will make the Evictor start considering application with just a single replica.
- `arm64_supported` (Boolean) If enabled, indicates arm64 nodes are present so the scheduling simulation includes them as valid bin-packing targets.
- `cycle_interval` (String) Configure the interval duration between Evictor operations. This property can be used to lower or raise the frequency of the Evictor's find-and-drain operations.
- `drain_rollback_timeout` (String) How long the evictor waits before rolling back a cordon when a drain attempt fails.
- `drain_timeout` (String) Maximum time the evictor waits for a node to fully drain before giving up.
- `dry_run` (Boolean) Enable/disable dry-run. This property allows you to prevent the Evictor from carrying any operations out and preview the actions it would take.
- `emit_node_related_pod_events` (Boolean) If enabled, Evictor emits Kubernetes events on pods when they are evicted as part of a node drain.
- `enabled` (Boolean) Enable/disable the Evictor policy. This will either install or uninstall the Evictor component in your cluster.
- `force_disable_karpenter_mode` (Boolean) If enabled, disables Karpenter-aware scheduling simulation even when Karpenter is detected.
- `force_disable_live_migration` (Boolean) If enabled, disables LIVE pod migration even when the cluster capability is detected.
- `force_disable_pod_mutations` (Boolean) If enabled, disables PodMutation CR application during scheduling simulation even when the cluster capability is detected.
- `force_disable_woop` (Boolean) If enabled, disables WOOP scheduling recommendations even when the cluster capability is detected.
- `ignore_pod_disruption_budgets` (Boolean) If enabled then Evictor will attempt to evict pods that have pod disruption budgets configured.
- `max_target_nodes_per_cycle` (Number) Upper bound on nodes drained in a single cycle.
- `min_target_nodes_per_cycle` (Number) Lower bound on nodes considered per cycle.
- `node_grace_period_minutes` (Number) Configure the node grace period which controls the duration which must pass after a node has been created before Evictor starts considering that node.
- `pod_eviction_failure_back_off_interval` (String) Configure the pod eviction failure back off interval. If pod eviction fails then Evictor will attempt to evict it again after the amount of time specified here.
- `pricing_awareness_enabled` (Boolean) If enabled, the evictor factors node cost into drain candidate selection, preferring to drain more expensive nodes first.
- `pricing_model` (Block List, Max: 1) Overrides the default cost coefficients used when pricing_awareness_enabled is true. (see [below for nested schema](#nestedblock--pricing_model))
- `scoped_mode` (Boolean) Enable/disable scoped mode. By default, Evictor targets all nodes in the cluster. This mode will constrain it to just the nodes which were created by CAST AI.
- `soft_tainting` (Boolean) If enabled, Evictor will use soft tainting (PreferNoSchedule) instead of hard cordoning after eviction.
- `target_node_percentage` (Number) Percentage of eligible nodes to consider per cycle, applied after min/max bounds.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))
- `windows` (Boolean) If enabled, Evictor will evict pods and nodes running Windows workloads.

### Read-Only

- `id` (String) The ID of this resource.
- `status` (String) Status provides indication whether the Evictor policy will be synced with Evictor helm chart - it will only be done if status is "Compatible".
